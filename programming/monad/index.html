Monad

2026年07月25日 プログラミング
  • Haskell
  • モナド
  • 圏論

プログラミングにおけるモナドの理解を深めるためのメモ。少しずつ書き足していく予定。 最終的には圏論的な定式化（モナドは自己関手の圏におけるモノイド対象である、という話）まで辿り着きたいが、 まずは Haskell における具体的な定義から出発する。

Haskell における Monad クラス

Haskell では、Monad は次のような型クラスとして定義される。

class Monad m where
  (>>=)  :: m a -> (a -> m b) -> m b
  (>>)   :: m a -> m b -> m b
  return :: a -> m a
  • return :: a -> m a は、素の値 a を「モナド m の文脈に包む」操作。
  • (>>=) （bind）は m a の中身を取り出して a -> m b を適用し、結果を m b として返す、モナド計算の合成演算子。
  • (>>) は m a >> m b = m a >>= \_ -> m b と定義でき、(>>=) の結果を捨てる版（前の計算の値を使わない逐次実行）。

したがって本質的なのは return と (>>=) の2つで、(>>) はそこから導出される。

モナド則

Monad のインスタンスは、型クラスの型として定義されるだけでなく、以下の3つの法則（モナド則）を満たす必要がある。ただし、これは Haskell の型システムによって強制されるものではなく、インスタンスを書く側が保証すべき性質。

  1. 左単位元則: return a >>= k = k a
  2. 右単位元則: m >>= return = m
  3. 結合律: m >>= (\x -> k x >>= h) = (m >>= k) >>= h

具体例: Maybe モナド

Maybe は「失敗しうる計算」を表す最も単純なモナド。定義は次の通り。

data Maybe a = Nothing | Just a

Monad インスタンスは次のように定義される。

instance Monad Maybe where
  return :: a -> Maybe a
  return x = Just x

  (>>=) :: Maybe a -> (a -> Maybe b) -> Maybe b
  Nothing  >>= _ = Nothing
  Just x   >>= f = f x
  • return は値 x を Just x に包むだけ。
  • (>>=) は、Nothing であれば以降の計算を一切行わずに Nothing を伝播させ、Just x であれば中身の x を取り出して f に渡す。

つまり Maybe モナドの (>>=) は「一度 Nothing になったら、それ以降の計算をすべてスキップする」という短絡評価（short-circuit）を実現している。これにより、失敗しうる計算を Maybe で包んでおけば、いちいち失敗をチェックするコードを書かずに (>>=) で繋げるだけでよくなる。

具体例として、整数の割り算を「0除算のときは失敗する計算」として書いてみる。

safeDiv :: Int -> Int -> Maybe Int
safeDiv _ 0 = Nothing
safeDiv x y = Just (x `div` y)

calc :: Int -> Int -> Int -> Maybe Int
calc x y z = safeDiv x y >>= \r -> safeDiv r z

calc 10 2 0 は safeDiv 10 2 が Just 5 を返し、続く safeDiv 5 0 が Nothing を返すので全体として Nothing になる。途中の Nothing チェックを自前で書かなくても、(>>=) の定義がそれを肩代わりしてくれている。

do 記法を使うと同じ計算は次のように書ける。do ブロックはこの (>>=) の連鎖の糖衣構文にすぎない。

calc :: Int -> Int -> Int -> Maybe Int
calc x y z = do
  r <- safeDiv x y
  safeDiv r z

モナド則も確認しておく。

  • 左単位元則: return a >>= k = Just a >>= k = k a が成り立つ。
  • 右単位元則: Nothing >>= return = Nothing、Just x >>= return = return x = Just x なので、いずれも元の値と一致する。
  • 結合律: Nothing の場合は両辺とも Nothing。Just x の場合は両辺とも k x >>= h に簡約される。

圏論におけるモナドの定義

圏、関手、自然変換は既知とする。

圏 \(\mathcal{C}\) 上のモナドとは、自己関手

\[ T : \mathcal{C} \to \mathcal{C} \]

と、2つの自然変換

\[ \eta : \mathrm{Id}_{\mathcal{C}} \Rightarrow T, \qquad \mu : T^2 \Rightarrow T \]

の組 \((T, \eta, \mu)\) であって、以下の2つの図式を可換にするもの。ここで \(T^2 = T \circ T\)、\(T^3 = T \circ T \circ T\) である。

結合律（\(T^3 \Rightarrow T\) として、\(\mu \circ \mu T = \mu \circ T\mu\)）　任意の対象 \(X\) について次の図式が可換。

\[ \begin{CD} T^3X @>{T\mu_X}>> T^2X \\ @V{\mu_{TX}}VV @VV{\mu_X}V \\ T^2X @>{\mu_X}>> TX \end{CD} \]

単位律（\(T \Rightarrow T\) として、\(\mu \circ \eta T = \mu \circ T\eta = \mathrm{id}_T\)）　任意の対象 \(X\) について次の2つの図式が可換。

\[ \begin{CD} TX @>{\eta_{TX}}>> T^2X \\ @| @VV{\mu_X}V \\ TX @= TX \end{CD} \qquad \begin{CD} TX @>{T\eta_X}>> T^2X \\ @| @VV{\mu_X}V \\ TX @= TX \end{CD} \]

Haskell の定義との対応

Haskell の Monad クラスは return と (>>=) を基本演算としていたが、これは圏論での η・μ の定義とは一見形が異なる。両者は次のように対応している。

  • T は型構築子 m（Functor インスタンス）に対応する。
  • η は return :: a -> m a に対応する。
  • μ は join :: m (m a) -> m a に対応する（m (m a) は \(T^2 a\) に相当）。

実際、Haskell の Monad は return と (>>=) の代わりに fmap（Functor から）・return・join の3つで定義することもでき、(>>=) はそこから次のように導ける。

(>>=) :: Monad m => m a -> (a -> m b) -> m b
m >>= f = join (fmap f m)

このとき、Haskell の3つのモナド則（左単位元則・右単位元則・結合律）は、上の結合律・単位律の可換図式を各対象上で書き下したものに一致する。たとえば右単位元則 m >>= return = m は join (fmap return m) = m となり、これは単位律 \mu_X \circ T\eta_X = \mathrm{id}_{TX} そのものである。
