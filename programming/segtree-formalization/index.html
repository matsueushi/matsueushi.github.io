セグメント木の理屈を調査

2026年08月15日 プログラミング
  • セグメント木

競技プログラミングの文脈で出てくるセグメント木について「どう使うか」ではなく、「なぜ使えるのか」を考察します。

お断り

前提

セグメント木に関する基本的な知識を仮定します。また、モノイド、圏、関手と言った数学的な概念を断りなく利用し、圏はすべて small を仮定します。モノイドは可換性を仮定しません。

参考文献

セグメント木自体の、日本語の概要については “セグメント木を徹底解説！0から遅延評価やモノイドまで”1、英語だと “Segment Tree”2 が細かく書いてありそうです。

セグメント木にモノイドがなぜ適した抽象化なのかを具体例とともに説明してある、数学・アルゴリズム的な側面に重点を置いた、理論寄りの内容としてコンパクトにまとまっているのが “Generalizing Segment Trees”3 です。

セグメント木に載せることができる代数的構造について可能な限り self-contained であるように書かれているノートが “セグメント木と代数構造の理論”4 です。こちらのノートにはセグメント木に乗る代数構造のモノイドから圏への拡張について触れられていますが、同作者による 2018 年の記事 “セグメント木の上に乗る構造はモノイドではなく圏である”5 では同様の考察があり、ノートに書かれていなかった考察が “セグメント木, より一般に「区間積クエリを高速計算する方法」の圏によるモデル”6 で行われています。 “セグメント木に圏が乗るか？”7 ではこれらの議論に対するコメントといった形で厳密化の試みがなされています。

本記事では別の論文の議論にインスパイアされた別の方法を用います。 “Testing Calibration in Nearly-Linear Time”8 では双対セグメント木に対してデータ構造を具体的に構成した後、代数的構造との整合性を証明しています。

別のアプローチとして定理証明系 Coq を用いてセグメント木のクエリの正しさを証明する “セグメント木の形式的証明”9 があります。

セグメント木の構成

一点更新・区間取得ができるセグメント木を構成します。

設定

  • モノイド \(M = (M, \cdot, e)\)、長さ \(n = 2^r\)(一般の \(n\) は単位元でパディングして仮定してよい)。
  • 完全二分木 \(T\)(深さ \(r\))を考え、各ノード \(\tau \in T\) に区間 \(\mathrm{seg}(\tau) \subseteq [1:n]\) を対応させる。根 \(\tau_0\) は \(\mathrm{seg}(\tau_0) = [1:n]\)、子は前半・後半に分割、葉は \(\mathrm{seg}(\tau) = \{i\}\)(単一のインデックス)。
  • 各ノード \(\tau\) に、モノイドの元 \(v_\tau \in M\) を保持する。不変条件として、常に \[ v_\tau = \bigodot_{i \in \mathrm{seg}(\tau)} a_i \] が成り立つようにする(\(a_i\) は現在の配列の値、\(\bigodot\) はインデックス順に取ったモノイド積)。

初期化 Build

すべての \(i\) について \(a_i \leftarrow e\) とし、木の全ノードで \(v_\tau \leftarrow e\)(単位元の積は単位元なので不変条件を満たす)。

Set(i, c): 一点更新

Set(i, c, τ):
  if seg(τ) = {i}:
    v_τ ← c            # 葉なので直接書き換え
    return
  let τ1, τ2 を τ の子とする
  if i ∈ seg(τ1):
    Set(i, c, τ1)
  else:
    Set(i, c, τ2)
  v_τ ← v_τ1 · v_τ2     # 子の更新後に再計算

Set(i, c) を Set(i, c, τ0)(ルートから呼ぶ)として定義します。

Query(l, r): 区間 [l, r] の総積

Query(l, r, τ):
  if seg(τ) ∩ [l, r] = ∅:
    return e             # 単位元(何も無ければ影響しない)
  if seg(τ) ⊆ [l, r]:
    return v_τ            # 部分木を丸ごと使える
  let τ1, τ2 を τ の子とする
  return Query(l, r, τ1) · Query(l, r, τ2)

Query(l, r) を Query(l, r, τ0) として定義します。

成り立って欲しい性質

記法として、区間 \(I \subseteq [1:n]\) に対して \(\bigodot_{i \in I} a_i\) を「\(I\) の要素をインデックス順に取ったモノイド積」とし、\(I = \emptyset\) のときは単位元 \(e\) と約束します(空積)。

補題1(Set操作の不変条件保存)

主張. 任意の木のノード \(\tau\) について、任意の Set 呼び出し列の後で

\[ v_\tau = \bigodot_{i \in \mathrm{seg}(\tau)} a_i \]

が成り立つ(初期状態でも成立、以降の任意の Set 呼び出しの後も成立)。

証明. 初期状態ではすべての \(a_i = e\) かつすべての \(v_\tau = e\) なので、空でない \(\mathrm{seg}(\tau)\) についても \(\bigodot_{i} e = e\) より成立。

帰納法のステップとして、ある呼び出し \(\mathrm{Set}(i,c)\) の前後で不変条件が保たれることを示す。根から葉 \(i\) までのパスを \(\tau_0 \to \tau_1 \to \cdots \to \tau_r\) とする。

パス外のノード. \(\tau \notin \{\tau_0,\ldots,\tau_r\}\) ならば \(i \notin \mathrm{seg}(\tau)\)(パス上のノードだけが \(i\) を含む区間を持つため)。アルゴリズムはこれらのノードの \(v_\tau\) を書き換えないし、\(a_i\) 以外の値も変わらないので、\(\bigodot_{j \in \mathrm{seg}(\tau)} a_j\) の値そのものが変化しない。よって不変条件は変化なく保たれる。

パス上のノード(葉から根への帰納法).

  • 葉 \(\tau_r\)(\(\mathrm{seg}(\tau_r) = \{i\}\)): アルゴリズムは \(v_{\tau_r} \leftarrow c\) と直接書き換える。新しい配列では \(a_i = c\) なので \(\bigodot_{j \in \{i\}} a_j = c = v_{\tau_r}\)。成立。
  • \(\tau_k\)(\(0 \le k < r\)、子は \(\tau_{k+1}\) とパス外の兄弟 \(\tau'\)): 帰納法の仮定より \(v_{\tau_{k+1}} = \bigodot_{j \in \mathrm{seg}(\tau_{k+1})} a_j\)(再帰呼び出しが先に完了しているため)。また \(\tau'\) はパス外なので上で示した通り \(v_{\tau'} = \bigodot_{j \in \mathrm{seg}(\tau')} a_j\) が(新しい配列に対しても)既に成立している。アルゴリズムは \(v_{\tau_k} \leftarrow v_{\tau_{k+1}} \cdot v_{\tau'}\)(または逆順、\(\tau_{k+1}\) が右の子なら \(v_{\tau'}\cdot v_{\tau_{k+1}}\))と計算する。\(\mathrm{seg}(\tau_k) = \mathrm{seg}(\tau_{k+1}) \sqcup \mathrm{seg}(\tau')\)(インデックス順を保った非交和)なので、モノイドの結合律により \[ v_{\tau_k} = \Bigl(\bigodot_{j \in \mathrm{seg}(\tau_{k+1})} a_j\Bigr)\cdot\Bigl(\bigodot_{j \in \mathrm{seg}(\tau')} a_j\Bigr) = \bigodot_{j \in \mathrm{seg}(\tau_k)} a_j. \] 成立。∎

ここで使っているのは結合律(と単位元の存在、空積のため)のみで、可換性は不要です。

補題2(Query操作の正当性)

主張. 補題1の不変条件が成り立っている状態で、任意のノード \(\tau\) について

\[ \mathrm{Query}(l,r,\tau) = \bigodot_{i \in \mathrm{seg}(\tau) \cap [l,r]} a_i. \]

証明. \(\tau\) についての(木の高さに関する)帰納法。

  • \(\mathrm{seg}(\tau) \cap [l,r] = \emptyset\): アルゴリズムは \(e\) を返す。空積の約束により \(\bigodot_{i \in \emptyset} a_i = e\)。成立。
  • \(\mathrm{seg}(\tau) \subseteq [l,r]\): アルゴリズムは \(v_\tau\) を返す。補題1より \(v_\tau = \bigodot_{i \in \mathrm{seg}(\tau)} a_i\)、かつ \(\mathrm{seg}(\tau) \subseteq [l,r]\) より \(\mathrm{seg}(\tau)\cap[l,r] = \mathrm{seg}(\tau)\)。成立。
  • それ以外(\(\mathrm{seg}(\tau)\cap[l,r]\) が \(\mathrm{seg}(\tau)\) の空でない真部分集合): 子 \(\tau_1,\tau_2\) について、帰納法の仮定(部分木は真に小さいので適用可能)より \[ \mathrm{Query}(l,r,\tau_1) = \bigodot_{i \in \mathrm{seg}(\tau_1)\cap[l,r]} a_i, \quad \mathrm{Query}(l,r,\tau_2) = \bigodot_{i \in \mathrm{seg}(\tau_2)\cap[l,r]} a_i. \] \(\mathrm{seg}(\tau)\cap[l,r] = (\mathrm{seg}(\tau_1)\cap[l,r]) \sqcup (\mathrm{seg}(\tau_2)\cap[l,r])\)(順序を保った非交和)なので、再び結合律により \[ \mathrm{Query}(l,r,\tau_1)\cdot\mathrm{Query}(l,r,\tau_2) = \bigodot_{i \in \mathrm{seg}(\tau)\cap[l,r]} a_i. \] これがアルゴリズムの返す値そのものなので成立。∎

系. \(\mathrm{seg}(\tau_0) = [1:n] \supseteq [l,r]\) なので、\(\mathrm{Query}(l,r) = \mathrm{Query}(l,r,\tau_0) = \bigodot_{i \in [l,r]} a_i\)。これが求めたかった性質です。

遅延評価版セグメント木

ここまでの構成では更新が一点、取得が区間でした。次に「区間更新・区間取得」ができる遅延評価版(lazy segment tree)を構成し、同じ流儀で正当性を示します。

設定

  • データのモノイド \(M = (M, \cdot, e)\)、長さ \(n = 2^r\)(これまでと同じ)。
  • 作用素のモノイド \(F = (F, \circ, \mathrm{id})\) と、作用 \(F \times M \to M,\ (f, x) \mapsto f(x)\) で、次を満たすもの。
    • (A1) \(\mathrm{id}(x) = x\)
    • (A2) \((f \circ g)(x) = f(g(x))\)(\(g\) を先に当てる。「\(f\) after \(g\)」)
    • (A3) \(f(x \cdot y) = f(x) \cdot f(y)\)(各 \(f\) は \(M\) の半群準同型)
  • 各ノード \(\tau\) は \(v_\tau \in M\) に加えて遅延タグ \(\mathrm{lz}_\tau \in F\) を持つ。

タグの意味は「\(v_\tau\) には \(\mathrm{lz}_\tau\) は既に反映されているが、\(\tau\) の子孫にはまだ伝えていない」です。この約束を式にするため、\(\tau\) の真の祖先を根から順に \(\tau_0 \to \cdots \to \tau_{k-1}\)(\(\tau_{k-1}\) が親)として

\[ g_\tau := \mathrm{lz}_{\tau_0} \circ \mathrm{lz}_{\tau_1} \circ \cdots \circ \mathrm{lz}_{\tau_{k-1}} \]

とおきます(根では空合成なので \(g_{\tau_0} = \mathrm{id}\))。子 \(c\) について \(g_c = g_\tau \circ \mathrm{lz}_\tau\) が成り立つことを以下で何度も使います。

不変条件 (I) は次です。

\[ \text{(I)}\quad \forall \tau:\ g_\tau(v_\tau) = \bigodot_{i \in \mathrm{seg}(\tau)} a_i. \]

「祖先に溜まっているタグを全部当てれば真の区間積になる」という条件で、タグがすべて \(\mathrm{id}\) なら元の不変条件に戻ります。

初期化 Build

すべての \(a_i \leftarrow e\)、\(v_\tau \leftarrow e\)、\(\mathrm{lz}_\tau \leftarrow \mathrm{id}\)。\(g_\tau = \mathrm{id}\) なので (I) は元の Build と同じ理由で成立。

Push(τ): タグの下方伝播(\(\tau\) は内部ノード)

Push(τ):
  let τ1, τ2 を τ の子とする
  for c in {τ1, τ2}:
    v_c  ← lz_τ(v_c)
    lz_c ← lz_τ ∘ lz_c
  lz_τ ← id

Apply(l, r, f): 区間 \([l,r]\) の各 \(a_i\) を \(f(a_i)\) に置き換える

Apply(l, r, f, τ):
  if seg(τ) ∩ [l, r] = ∅:
    return
  if seg(τ) ⊆ [l, r]:
    v_τ  ← f(v_τ)
    lz_τ ← f ∘ lz_τ          # 子孫への伝播は保留
    return
  Push(τ)                    # 子に降りる前に必ず伝播
  let τ1, τ2 を τ の子とする
  Apply(l, r, f, τ1)
  Apply(l, r, f, τ2)
  v_τ ← v_τ1 · v_τ2

Query(l, r): 区間 \([l,r]\) の総積

Query(l, r, τ):
  if seg(τ) ∩ [l, r] = ∅:
    return e
  if seg(τ) ⊆ [l, r]:
    return v_τ
  Push(τ)
  let τ1, τ2 を τ の子とする
  return Query(l, r, τ1) · Query(l, r, τ2)

いずれも根 \(\tau_0\) から呼びます。葉では \(\mathrm{seg}(\tau)\) が一点集合なので「空」か「完全被覆」のどちらかになり、Push が葉で呼ばれることはありません。したがって葉のタグは特別扱い不要です(常に \(\mathrm{id}\) のままでもよいし、放置してもよい)。

成り立って欲しい性質

以下、「\(\tau\) の部分木」とは \(\tau\) 自身とその子孫の集合、「\(\tau\) の部分木で (I) が成り立つ」とはその集合の各ノードで (I) が成り立つことを指します。証明を部分木ごとに局所化しておくと、兄弟への再帰の前後で祖先ノードの (I) が一時的に壊れていても問題にならず、議論がすっきりします。

補題3(Push は不変条件を保つ)

主張. 内部ノード \(\tau\) について、\(\tau\) の部分木で (I) が成り立っているとき、Push(τ) の後も \(\tau\) の部分木で (I) が成り立つ。配列 \(a\) は変化せず、\(\tau\) の部分木の外側は一切変更されない。さらに Push 後は \(g_{\tau_1} = g_{\tau_2} = g_\tau\)。

証明. Push が書き換えるのは \(\mathrm{lz}_\tau\) と、子 \(c\) の \(v_c, \mathrm{lz}_c\) のみ。

  • \(\tau\) 自身: \(v_\tau\) も \(g_\tau\)(真の祖先のタグの合成)も変わらない。成立。
  • 子 \(c\): 変更前は \(g_c = g_\tau \circ \mathrm{lz}_\tau\)。変更後は \(g'_c = g_\tau \circ \mathrm{id} = g_\tau\)、\(v'_c = \mathrm{lz}_\tau(v_c)\)。よって (A2) より \(g'_c(v'_c) = g_\tau(\mathrm{lz}_\tau(v_c)) = g_c(v_c)\)。値は変わらないので成立。
  • \(c\) の真の子孫 \(\delta\): 変更前 \(g_\delta = g_\tau \circ \mathrm{lz}_\tau \circ \mathrm{lz}_c \circ (\text{残り})\)。変更後は \(g'_\delta = g_\tau \circ \mathrm{id} \circ (\mathrm{lz}_\tau \circ \mathrm{lz}_c) \circ (\text{残り})\)。合成の結合律よりこれは同じ写像。\(v_\delta\) も変わらないので成立。∎

補題4(Apply の正当性)

主張. \(\tau\) の部分木で (I) が成り立ち、かつ \(g_\tau = \mathrm{id}\) のとき、Apply(l, r, f, τ) の後、\(\tau\) の部分木で (I) が新しい配列 \(a'\) に対して成り立つ。ここで \(a'_i = f(a_i)\)(\(i \in \mathrm{seg}(\tau) \cap [l,r]\))、それ以外は \(a'_i = a_i\)。また \(\tau\) の部分木の外側は変更されない。

証明. 木の高さに関する帰納法。

  • \(\mathrm{seg}(\tau) \cap [l,r] = \emptyset\): 何もしない。\(a' = a\) なので成立。
  • \(\mathrm{seg}(\tau) \subseteq [l,r]\): このとき \(a'_i = f(a_i)\)(\(i \in \mathrm{seg}(\tau)\))。
    • \(\tau\) 自身: \(g_\tau = \mathrm{id}\) なので \(g_\tau(v'_\tau) = f(v_\tau) = f\bigl(\bigodot_{i \in \mathrm{seg}(\tau)} a_i\bigr) = \bigodot_{i \in \mathrm{seg}(\tau)} f(a_i) = \bigodot_{i \in \mathrm{seg}(\tau)} a'_i\)。3つ目の等号で (A3) を積の項数について繰り返し使った。成立。
    • 真の子孫 \(\delta\): 変更前 \(g_\delta = g_\tau \circ \mathrm{lz}_\tau \circ (\text{残り}) = \mathrm{lz}_\tau \circ (\text{残り})\)。変更後 \(g'_\delta = g_\tau \circ (f \circ \mathrm{lz}_\tau) \circ (\text{残り}) = f \circ g_\delta\)。ここでも \(g_\tau = \mathrm{id}\) を使っている。\(v_\delta\) は不変なので \(g'_\delta(v_\delta) = f(g_\delta(v_\delta)) = f\bigl(\bigodot_{i \in \mathrm{seg}(\delta)} a_i\bigr) = \bigodot_{i \in \mathrm{seg}(\delta)} a'_i\)(\(\mathrm{seg}(\delta) \subseteq \mathrm{seg}(\tau) \subseteq [l,r]\) と (A3))。成立。
    • 部分木の外側は触っていない。
  • それ以外: Push(τ) により(補題3)部分木で (I) は保たれ、\(a\) は不変、\(g_{\tau_1} = g_{\tau_2} = g_\tau = \mathrm{id}\)。 Apply(τ1) に帰納法の仮定を使うと、\(\tau_1\) の部分木で (I) が \(a^{(1)}\)(\(\mathrm{seg}(\tau_1) \cap [l,r]\) 上だけ \(f\) を当てたもの)に対して成り立ち、\(\tau_1\) の部分木の外側は不変。特に \(\mathrm{lz}_\tau\) は \(\mathrm{id}\) のままで \(g_{\tau_2} = \mathrm{id}\)、また \(\tau_2\) の部分木は手つかずで、\(\mathrm{seg}(\tau_2)\) 上では \(a^{(1)} = a\) なので \(\tau_2\) の部分木で (I) は \(a^{(1)}\) に対して成立している。 よって Apply(τ2) にも帰納法の仮定が使え、\(\tau_2\) の部分木で (I) が \(a'\)(\(a^{(1)}\) にさらに \(\mathrm{seg}(\tau_2) \cap [l,r]\) 上で \(f\) を当てたもの)に対して成立。\(\mathrm{seg}(\tau_1), \mathrm{seg}(\tau_2)\) は交わらないので、この \(a'\) は主張の \(a'\) そのもの。\(\tau_1\) の部分木は Apply(τ2) で触られず、\(\mathrm{seg}(\tau_1)\) 上で \(a' = a^{(1)}\) なので、そちらの (I) も \(a'\) に対して成立したまま。 最後に \(v_\tau \leftarrow v_{\tau_1} \cdot v_{\tau_2}\)。\(g_{\tau_1} = g_{\tau_2} = \mathrm{id}\) より \(v_{\tau_j} = \bigodot_{i \in \mathrm{seg}(\tau_j)} a'_i\) なので、補題1と同じく \(M\) の結合律により \(v_\tau = \bigodot_{i \in \mathrm{seg}(\tau)} a'_i\)。\(g_\tau = \mathrm{id}\) なので (I) 成立。∎

補題5(Query の正当性)

主張. \(\tau\) の部分木で (I) が成り立ち、かつ \(g_\tau = \mathrm{id}\) のとき、Query(l, r, τ) は \(\bigodot_{i \in \mathrm{seg}(\tau) \cap [l,r]} a_i\) を返す。呼び出し後も \(\tau\) の部分木で (I) は成り立ち、\(a\) は変化せず、部分木の外側は変更されない。

証明. 高さに関する帰納法。空の場合は \(e\)(空積)。完全被覆の場合は \(v_\tau = g_\tau(v_\tau) = \bigodot_{i \in \mathrm{seg}(\tau)} a_i\)。それ以外の場合は、Push(τ) で (I) を保ったまま \(g_{\tau_1} = g_{\tau_2} = \mathrm{id}\) にしてから子に帰納法の仮定を適用し、あとは補題2の3つ目の場合と同じ(順序を保った非交和と結合律)。∎

系. 根では \(g_{\tau_0} = \mathrm{id}\) が自動的に成り立つので、Build 直後から Apply と Query をどの順に何回呼んでも (I) が保たれ、Query(l, r) は常に現在の配列に対する \(\bigodot_{i \in [l,r]} a_i\) を返す。

一点更新 Set(i, c) が欲しければ、元の Set の再帰の直前に Push(τ) を挟むだけで同じ議論が通ります(葉に着いたとき \(g = \mathrm{id}\) になっている)。

注意

どこで何を使ったか. \(M\) の結合律は子の値を合成するときに(補題1と同じ)、\(F\) の結合律とタグの合成 (A2) は Push が値を変えないことに、そして準同型条件 (A3) は「完全被覆ノードにタグを乗せる」一手だけに使われました。(A3) が要る理由は、\(v_\tau\) が区間全体の積 \(\bigodot a_i\) の形で持たれているのに対し、やりたい更新は各項に \(f\) を当てることであり、この2つが一致するのがちょうど準同型のときだからです。可換性はやはり \(M\) にも \(F\) にも要りません。

なぜ Push が必要か. 補題4の完全被覆の場合の証明で \(g_\tau = \mathrm{id}\) を使っています。これがないと \(g_\tau(f(v_\tau))\) と \(f(g_\tau(v_\tau))\) が一般には一致しません。つまり Push は \(F\) の合成が非可換であることへの対処で、\(F\) が可換なら Push を省いて Query 側で祖先タグを合成しながら降りる実装(あるいは Apply でも下方伝播せず、上に戻るときに \(v_\tau \leftarrow \mathrm{lz}_\tau(v_{\tau_1} \cdot v_{\tau_2})\) と再計算する実装)が正当化できます。

Query を副作用なしにする変種. Query(l, r, τ, g) の形で祖先タグの合成 \(g\) を引数に持ち回り、完全被覆なら \(g(v_\tau)\) を返し、子へは \(g \circ \mathrm{lz}_\tau\) を渡す、とすれば Push なしでも補題5と同じ主張が成り立ちます((A2) だけで示せる)。

例. (A3) を満たすには \(M\) の取り方に注意が要ります。

  • 区間加算・区間和: \(M = \mathbb{Z}\) の和で \(f(x) = x + c\) とすると \(f(x + y) \ne f(x) + f(y)\) なので (A3) が壊れる。\(M = \{(s, \ell)\}\)(和と長さ)として \(f(s, \ell) = (s + c\ell, \ell)\) とすれば準同型になる。区間アフィン \(f(s,\ell) = (as + b\ell, \ell)\) や区間代入 \(f(s,\ell) = (c\ell, \ell)\) も同様。
  • 区間加算・区間 min: \(M = (\mathbb{Z} \cup \{\infty\}, \min)\)、\(f(x) = x + c\)。\(\min(x, y) + c = \min(x + c, y + c)\) なのでそのまま (A3) が成り立つ。

パディングについて. \(n\) を \(2^r\) に単位元でパディングした場合、\([l,r]\) は本来の範囲内なのでパディング部分の \(a_i = e\) が更新されることはなく、上の議論はそのまま通ります。\(f(e) = e\) は使っていません。

計算量. Query と同じく、各深さで「部分的に交わる」ノードは高々2つなので、Apply も Query も訪問ノード数は \(O(\log n)\)、Push は訪問ノードごとに定数回で、1回あたり \(O(\log n)\) のままです。
